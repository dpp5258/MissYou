## 二、Question ID 设计（独立命名空间）

### 2.1 去重机制

`is_question_recent(sheet, game_type, question_id)` 三重过滤：

```python
if row[1] == game_type and row[2] == question_id and row[0][:10] >= cutoff:
    return True
```

三个游戏的 QID 天然隔离，**不需要统一命名空间**：

```
游戏记录表
┌─────────────┬──────────────────┬────────────┐
│ 游戏类型     │ 题目ID           │ 说明        │
├─────────────┼──────────────────┼────────────┤
│ number_puzzle│ a3f7b2c1        │ hash(排序数字+目标) │
│ memory_match │ d4e8f9a0        │ hash(seed+布局)    │
│ word_match   │ b1c2d3e4        │ hash(词对集合)     │
│ number_puzzle│ a3f7b2c1        │ ⚠️ 7天内同游戏同题拦截 │
└─────────────┴──────────────────┴────────────┘
```

### 2.2 各游戏 QID 生成规则

| 游戏 | question_id() | 含义 |
|------|---------------|------|
| 数字拼接 | `hash(排序后的4个数字 + "-" + 目标数)` | 同数字+同目标=同题 |
| 记忆翻牌 | `hash(seed + layout)` | 同种子+同布局=同卡牌排列 |
| 单词匹配 | `hash(排序后的词对集合)` | 同一组单词=同题 |

## 三、UI 布局方案

### 3.1 现状问题

当前用 `st.selectbox` 单选，只适合一款游戏：

```python
st.selectbox("选择游戏", game_names)  # 只有一项时无意义
```

### 3.2 方案：Tab 切换

三款游戏并排展示，用户点击 Tab 切换，直观且互不干扰：

```
┌───────────────────────────────────────────────┐
│  🎮 小游戏赚思念值                              │
│                                                │
│  ┌───────────┬───────────┬───────────┐         │
│  │ 🔢 数字拼接│ 🃏 记忆翻牌│ 📝 单词匹配│         │
│  └───────────┴───────────┴───────────┘         │
│  ────────────────────────────────────          │
│                                                │
│  [当前选中游戏的 HTML iframe 渲染区域]           │
│                                                │
│  答对 +370 思念值 · 每天无限次 · 7天内不重复     │
└───────────────────────────────────────────────┘
```

### 3.3 实现方式

两种可选方案：

**方案 A：`st.tabs`（推荐）**

```python
# app.py render_user_page() 中
tabs = st.tabs([g.name for g in games])
for tab, game in zip(tabs, games):
    with tab:
        st.caption(f"答对 +{game.score} 思念值 · 每天无限次 · 7天内不重复")
        game.render(game, sheet)
```

优点：
- Streamlit 原生组件，自动处理切换
- session state 独立，切换 Tab 不丢失状态
- 代码改动最小（只改 app.py 的游戏渲染区域）

缺点：
- 三个 Tab 同时渲染，首次加载会创建三个 iframe
- 但三个 iframe 各自独立，不互相影响

**方案 B：`st.radio` + 条件渲染**

```python
choice = st.radio("选择游戏", game_names, horizontal=True)
selected = next(g for g in games if g.name == choice)
selected.render(selected, sheet)
```

优点：每次只渲染一个 iframe，轻量
缺点：切换游戏会销毁/重建 iframe，丢失当前状态

**选择：方案 A（`st.tabs`）**，因为：
- 记忆翻牌进行到一半切换到数字拼接再切回来，需要保留进度
- `st.tabs` 会保持每个 Tab 的 session state
- 首次加载性能差别可以忽略

#### 接口映射

#### 题目生成

```python
def generate_question() -> dict:
    """随机生成卡牌布局"""
    layouts = {
        "easy": (4, 3),    # 12张=6对
        "hard": (4, 4),    # 16张=8对
    }
    difficulty = random.choice(["easy", "hard"])
    cols, rows = layouts[difficulty]
    pair_count = (cols * rows) // 2
    
    emojis = ["🐶","🐱","🐭","🐹","🐰","🦊","🐻","🐼",
              "🐨","🐯","🦁","🐮","🐷","🐸","🐵","🐔"]
    chosen = random.sample(emojis, pair_count)
    cards = chosen * 2
    random.shuffle(cards)
    
    # seed 用于 question_id
    seed = random.randint(0, 10**9)
    
    return {
        "cards": cards,           # 卡牌 emoji 列表
        "cols": cols,
        "rows": rows,
        "difficulty": difficulty,
        "seed": seed,
    }
```

#### 答案验证

```python
def validate_answer(question_data: dict, user_answer) -> bool:
    """
    前端提交的数据：
    {
        action: 'submit',
        total_flips: 30,
        time_seconds: 45,
    }
    """
    # 翻牌次数合理性：最少 pairs*2 次，超出 3 倍视为异常
    pair_count = len(question_data["cards"]) // 2
    min_flips = pair_count * 2
    max_flips = pair_count * 6  # 超过 6 倍不合理
    
    flips = user_answer.get("total_flips", 0)
    if flips < min_flips or flips > max_flips:
        return False
    
    # 时间合理性：至少 2 秒，至多 10 分钟
    time_s = user_answer.get("time_seconds", 0)
    if time_s < 2 or time_s > 600:
        return False
    
    return True
```

#### 题目 ID

```python
def make_question_id(question_data: dict) -> str:
    seed = question_data.get("seed", 0)
    layout = f"{question_data.get('cols')}x{question_data.get('rows')}"
    key = f"{seed}-{layout}"
    return hashlib.md5(key.encode()).hexdigest()[:8]
```

#### 前端交互流程

```
初始状态：所有卡牌背面朝上
  ↓ 点击第1张牌 → 翻开（动画）
  ↓ 点击第2张牌 → 翻开（动画）
  ├─ 匹配成功 → 两张牌保持翻开，变灰/打勾
  └─ 匹配失败 → 两张牌翻回（延迟 0.8s）
  ↓
全部配对完成 → 自动 postMessage 提交
```

关键 JS 状态：
```js
let cards = [];           // 卡牌列表
let flipped = [];         // 当前翻开的索引（最多2个）
let matched = [];         // 已配对的索引集合
let flipCount = 0;        // 翻牌次数
let timerStart = null;    // 计时起点
let locked = false;       // 等待翻回期间锁定点击
```

#### 得分规则

```
基础分 = 370
表现系数 = 最优步数 / 实际步数
最优步数 = 对数 × 2（每次都一次配对成功，实际不可能）

最终得分 = 基础分 × max(0.5, 表现系数)
```

表现系数在**后端**计算（前端只传原始数据，服务端算分防作弊）：

```python
# submit_game_score 中
if game.game_id == "memory_match":
    pair_count = len(question_data["cards"]) // 2
    optimal = pair_count * 2
    actual = user_answer["total_flips"]
    multiplier = max(0.5, optimal / actual)
    game.score = int(370 * multiplier)
```

#### 题目生成

```python
def generate_question() -> dict:
    difficulty = random.choice(["easy", "hard"])
    pool = WORD_BANK[difficulty]
    count = random.randint(8, 12)
    pairs = random.sample(pool, min(count, len(pool)))
    
    # 打乱英文和中文的显示顺序
    en_list = [p[0] for p in pairs]
    zh_list = [p[1] for p in pairs]
    random.shuffle(en_list)
    random.shuffle(zh_list)
    
    return {
        "pairs": pairs,        # 正确答案 [(en, zh), ...]
        "en_display": en_list, # 打乱后的英文显示顺序
        "zh_display": zh_list, # 打乱后的中文显示顺序
        "difficulty": difficulty,
        "count": len(pairs),
    }
```

#### 答案验证

```python
def validate_answer(question_data: dict, user_answer) -> bool:
    """前端提交用户匹配结果，后端核对"""
    expected = set((en, zh) for en, zh in question_data["pairs"])
    user_matches = set()
    for m in user_answer.get("matches", []):
        user_matches.add((m["en"], m["zh"]))
    
    return expected == user_matches
```

#### 题目 ID

```python
def make_question_id(question_data: dict) -> str:
    pairs = question_data.get("pairs", [])
    flat = sorted(f"{en}|{zh}" for en, zh in pairs)
    key = "|".join(flat)
    return hashlib.md5(key.encode()).hexdigest()[:8]
```

#### 前端交互

```
左列（英文）          右列（中文）
┌──────────┐         ┌──────────┐
│ ● apple  │         │ 苹果     │
│ ○ book   │         │ ● 猫     │  ← 点击中文释义
│ ○ cat    │         │ ○ 书     │
│ ○ dog    │         │ ○ 狗     │
└──────────┘         └──────────┘
     ↑ 先点击英文单词
```

交互规则：
1. 先点击英文单词（高亮选中）
2. 再点击中文释义
3. 匹配正确 → 两条同时消失（绿色闪烁）
4. 匹配错误 → 取消选中，错误计数 +1
5. 全部消除 → 自动提交

#### 得分规则

```
基础分 = 370
正确率 = 正确匹配数 / 总匹配数
错误惩罚 = max(0.3, 1 - 错误次数 * 0.1)

最终得分 = 基础分 × 正确率 × 错误惩罚
```

## 六、`submit_game_score` 的微调

当前 `submit_game_score` 直接用 `game.score`。记忆翻牌和单词匹配需要**动态计算得分**。改动方案：

```python
# app.py submit_game_score 中，第 5 步之前插入：

# 4.5 计算动态得分（部分游戏根据表现调整）
score = _calc_game_score(game, question_data, user_answer)

# 5. 读取当前余额
new_balance = state["balance"] + score
```

```python
def _calc_game_score(game, question_data, user_answer) -> int:
    """根据游戏类型和表现计算实际得分"""
    if game.game_id == "memory_match":
        pair_count = len(question_data["cards"]) // 2
        optimal = pair_count * 2
        actual = user_answer.get("total_flips", 999)
        multiplier = max(0.5, optimal / actual)
        return int(game.score * multiplier)
    
    if game.game_id == "word_match":
        errors = user_answer.get("errors", 0)
        penalty = max(0.3, 1 - errors * 0.1)
        return int(game.score * penalty)
    
    # 默认：固定得分
    return game.score
```

改动很小，控制在 15 行以内。
