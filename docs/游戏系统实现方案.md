# MissYou 游戏加分系统 — 实现方案

---

## 零、目标概述

为用户页面添加小游戏功能，用户（myc）可通过玩游戏自助赚取思念值，无需管理员手动操作。

| 需求 | 方案 |
|------|------|
| 每题得分 | **370 分**（答对即加） |
| 每日上限 | **无上限**，想玩多少玩多少 |
| 题目重复 | **7 天内同题不可再次得分** |
| 扩展性 | **新增游戏类型只需加一个模块 + 一行注册** |
| 架构 | **纯 Streamlit widget**，不嵌入 iframe，完全复用现有数据链路 |

## 一、现有数据流回顾

```
┌──────────────┐      ┌──────────────┐      ┌───────────────┐
│  Streamlit   │ ───→ │  get_gsheet() │ ───→ │  Google Sheets │
│  UI 交互     │ ←─── │  read/write   │ ←─── │  (免费数据库)   │
└──────────────┘      └──────────────┘      └───────────────┘
```

**现有管理员加分链路：**

```
管理员输入数量 → 点确认按钮
  → write_account_state(sheet, balance + amount, ...)
  → append_operation_log(sheet, "手动增加", "+500", new_balance, note)
  → st.rerun()
```

**游戏加分链路（完全遵循同一模式）：**

```
用户玩游戏 → 提交答案
  → 服务端验证答案（纯函数，不信任前端输入）
  → 检查 7 天重复（查 Google Sheet "游戏记录"）
  → [通过] write_account_state(sheet, balance + 370, ...)
  → append_operation_log(sheet, "游戏奖励-数字拼接", "+370", new_balance, f"题目#{qid}")
  → 记录题目使用到 "游戏记录" 工作表
  → st.balloons() + st.success("🎉 答对了！+370 思念值")
  → [失败] st.error("答案不对，再试试～")
```

**关键原则：** 游戏加分和现有管理员加分走**同一条写链路**（`write_account_state` + `append_operation_log`），只是在前面加了游戏验证逻辑。`app.py` 不需要动现有函数签名。

## 三、游戏注册机制（扩展性核心）

每款游戏都是一个 dataclass 实例，注册到 `GAME_REGISTRY`。后续加新游戏只需要写一个新模块 + 在注册表加一行。

```python
# game_engine.py

from dataclasses import dataclass
from typing import Callable, Any

@dataclass
class GameDef:
    """游戏定义 — 所有游戏类型统一接口"""
    game_id: str              # 唯一标识，如 "number_puzzle"
    name: str                 # 显示名称，如 "🔢 数字拼接运算"
    description: str          # 一句话介绍
    score: int                # 答对得分（统一 370）
    render: Callable          # 渲染函数 (game_def, sheet) -> None
    generate: Callable        # 出题函数 () -> dict（题目数据）
    validate: Callable        # 验证函数 (question_data, user_answer) -> bool
    question_id: Callable     # 题目ID函数 (question_data) -> str（用于去重）

# ─── 游戏注册表（加新游戏只改这里） ───

GAME_REGISTRY: dict[str, GameDef] = {}

def register_game(game: GameDef):
    """注册一款游戏"""
    GAME_REGISTRY[game.game_id] = game
```

## 五、7 天去重机制

```python
from datetime import date, timedelta

def is_question_recent(sheet, game_type: str, question_id: str) -> bool:
    """检查该题目 7 天内是否已经答对过"""
    try:
        ws = sheet.worksheet("游戏记录")
        all_rows = ws.get_all_values()
    except gspread.exceptions.WorksheetNotFound:
        return False  # 还没有记录，肯定没重复

    cutoff = (date.today() - timedelta(days=7)).strftime("%Y-%m-%d")

    for row in all_rows[1:]:              # 跳过表头
        if len(row) < 3:
            continue
        row_time = row[0][:10]            # 取日期部分
        row_game = row[1]
        row_qid = row[2]
        if row_game == game_type and row_qid == question_id and row_time >= cutoff:
            return True
    return False
```

**调用时机：** `submit_game_score()` 中，验证答案通过后、写库之前。

**数据量估算：** 假设每天玩 50 题，7 天 350 行，一年约 18000 行。Google Sheets 单表上限 1000 万单元格，7 列 × 18000 行 = 126000 单元格，完全够用。查询时遍历所有行，到几千行时约 0.1 秒，可接受。

**优化预留：** 如果未来行数超过 5000，可以改成先读最后 1000 行（因为新记录总是在末尾，7 天内的数据一定在最后）。

## 六、统一加分入口

```python
def submit_game_score(sheet, game: GameDef, question_data: dict, user_answer: str):
    """
    统一加分入口 — 所有游戏共用。
    返回: (success: bool, message: str, balance_after: int | None)
    """
    # 1. 生成题目 ID
    qid = game.question_id(question_data)

    # 2. 检查 7 天重复
    if is_question_recent(sheet, game.game_id, qid):
        return (False, "这道题 7 天内已经答过了，换一题试试吧～", None)

    # 3. 服务端验证答案
    if not game.validate(question_data, user_answer):
        return (False, "答案不对，再想想～", None)

    # 4. 读取当前余额
    state = read_account_state(sheet)
    new_balance = state["balance"] + game.score

    # 5. 写账户状态
    write_account_state(
        sheet, new_balance,
        state["daily_decay"],
        date.today().strftime("%Y-%m-%d"),
        state["start_date"],
    )

    # 6. 写操作日志
    append_operation_log(
        sheet,
        f"游戏奖励-{game.name}",
        f"+{game.score}",
        new_balance,
        f"题目#{qid}",
    )

    # 7. 写游戏记录（去重用）
    ws = sheet.worksheet("游戏记录")
    timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    question_snapshot = ",".join(f"{k}:{v}" for k, v in question_data.items())
    ws.append_row([timestamp, game.game_id, qid, question_snapshot, user_answer, game.score, new_balance])

    return (True, f"🎉 答对了！+{game.score} 思念值 ✨", int(new_balance))
```

**安全措施：**

| 层面 | 措施 |
|------|------|
| **不信任前端** | 验证 100% 在服务端执行（`game.validate()`），前端渲染只是 UI |
| **防重放** | 同一 `game_type + question_id` 7 天内不可再次加分 |
| **防注入** | 答案字符串仅做纯数学验证，不 `eval()`，不会执行用户代码 |
| **会计不可逆** | 每次加分写入三条记录（账户状态、操作日志、游戏记录），不留后门 |
| **无裸接口** | 用户路径只走 `submit_game_score()`，不可能绕过验证直接写库 |

## 七、数字拼接游戏 — 题目生成算法

这是技术核心。不用固定题库，采用**实时生成 + 枚举求解**的方式，题库无限。

```
出题流程:
1. 随机选 4 个数字（1-13，扑克牌范围，体验好）
2. 枚举这 4 个数字的所有排列（4! = 24 种）
3. 每种排列拼上 + - × ÷ 的不同括号结构（5 种括号模式）
4. 计算每种表达式结果
5. 收集所有可达的整数结果
6. 随机选一个作为目标数
7. 记录对应的算式作为"标准答案"
8. 题目 ID = hash(f"{sorted_nums}-{target}")  保证确定性
```

**5 种括号结构（覆盖所有可能）：**

```
((a op b) op c) op d
(a op (b op c)) op d
(a op b) op (c op d)
a op ((b op c) op d)
a op (b op (c op d))
```

**为什么不用 eval：** 写出所有合法表达式字符串，用 Python 的 `eval()` 只评估自己生成的表达式，永不用户输入作为 `eval()` 的参数。

**题目 ID 生成（确定性）：**

```python
import hashlib

def make_question_id(nums: list[int], target: int) -> str:
    key = f"{'-'.join(map(str, sorted(nums)))}-{target}"
    return hashlib.md5(key.encode()).hexdigest()[:8]
```

同一组数字 + 同一目标 → 同一 ID，保证去重逻辑正确。

## 十三、风险与注意事项

| 风险 | 应对 |
|------|------|
| Google Sheets 写频率限制（60次/分钟） | 单人游戏不太可能超过，如超了加 `time.sleep(1)` |
